# Яндекс Метрика

Веб-аналитика Яндекса: 108 методов API поверх счётчика сайта. Этот скилл даёт готовую команду
и словарь, чтобы отвечать на вопросы о трафике числами, а не догадками.

## Когда брать и когда не брать

**Берите**, когда спрашивают о посещаемости, источниках, конверсиях, поведении на сайте,
о целях и сегментах, о выгрузке сырых визитов.

**Не берите**: Google Analytics, Яндекс Директ (это про рекламу и ставки — другой API),
AppMetrica (мобильные приложения), Яндекс Вебмастер (индексация и поисковые запросы в выдаче).
Метрика знает про рекламу только то, что доехало до сайта.

## Что нужно один раз

OAuth-токен Яндекса в `YANDEX_API_KEY`. Выпускается на [oauth.yandex.ru](https://oauth.yandex.ru/client/new):
приложение с доступом `metrika:read` (для изменения данных — `metrika:write`).

```bash
export YANDEX_API_KEY=<токен>
```

Токена нет — так и скажите, не пытайтесь обойти. Ходить в веб-интерфейс Метрики вместо API
не нужно: там нет ничего, чего нет здесь, а числа оттуда невозможно перепроверить.

## Три команды

Всё идёт через один пакет, ставить заранее ничего не нужно:

```bash
# что вообще есть — 108 методов, поиск по подстроке
npx -y yandex-metrika-mcp-server catalog --search goal

# какие параметры у метода, какие обязательны
npx -y yandex-metrika-mcp-server describe metrika_stat_data

# вызов
npx -y yandex-metrika-mcp-server call metrika_stat_data \
  --ids <ID счётчика> \
  --dimensions ym:s:trafficSource \
  --metrics ym:s:visits,ym:s:users \
  --date1 7daysAgo --date2 today
```

Ответ — JSON с двумя ключами: `data` (то, что вернула Метрика) и `_meta` (что сделал сервер).
**`_meta` читать обязательно** — см. следующий раздел.

Полный список методов: [`references/methods.md`](references/methods.md).
Имена измерений и метрик: [`references/dimensions.md`](references/dimensions.md).

## Рабочий цикл

1. **Найти счётчик.** `call metrika_counter_list` — вернёт счётчики, к которым есть доступ.
   Если счётчик один, дальше можно не спрашивать; если несколько — уточните у человека, какой,
   а не берите первый.
2. **Понять, что считаем.** Название метрики из вопроса переведите в имена `ym:` по словарю.
   Не уверены в имени — `catalog --search`, документация метода, и только потом запрос.
3. **Собрать отчёт.** Форм шесть: таблица (`metrika_stat_data`), динамика по дням
   (`metrika_stat_bytime`), детализация (`metrika_stat_drilldown`), сводная
   (`metrika_stat_pivot`), сравнение (`metrika_stat_comparison`) и сравнение с детализацией
   (`metrika_stat_comparison_drilldown`).
4. **Прочитать `_meta`** и только потом делать вывод.
5. **Назвать в ответе период и то, что отсев роботов включён.** Число без периода — не число.

## Что команда делает за вас

| Что | Зачем | Где видно |
| --- | --- | --- |
| Добавляет `ym:s:isRobot=='no'` к отчётам Stat | Без него в «посетителях» сидят боты, и отчёт выглядит совершенно нормально | `_meta.applied_by_server` |
| Режет слишком длинный ответ | Выгрузка логов бывает в сотни мегабайт | `_meta.truncated_by_server` |
| Вычищает секреты из показанного URL | У части методов токен идёт параметром строки запроса | `_meta.request_url` |
| Повторяет запрос при 429 и 5xx | Разовый сбой сети не должен выглядеть как «данных нет» | `_meta.retries` |

Отсев роботов снимается флагом `--no-human-traffic-only`. Тогда сервер скажет об этом в
`_meta.notes` — и в ответе человеку это тоже надо назвать, иначе числа несопоставимы с прежними.

⚠️ **`_meta.truncated_by_server` означает, что данные неполные.** Считать сумму или долю по
урезанной выдаче нельзя: получится уверенное неверное число. Либо сузьте запрос, либо поднимите
`METRIKA_MAX_OUTPUT_CHARS`, либо листайте по `offset`.

## Ловушки: где число выходит неверным без всякой ошибки

Это главная часть скилла. Метрика на перечисленное ниже отвечает `200` и правдоподобными
числами — ошибки не будет, будет неверный ответ.

**Пространства имён не смешиваются.** Их семь; ходовые — `ym:s:` (визиты), `ym:pv:` (просмотры
страниц), `ym:ad:` (клики Директа). Класть измерение одного пространства и метрику другого
в один запрос нельзя — это честный 400. Вопрос «на какие страницы заходят» — это `ym:pv:`,
а не `ym:s:`. Единственное место, где чужой префикс допустим, — `filters`.
Пространства `ym:u:` не существует, что бы ни говорили чужие шпаргалки.

**Отсев роботов не работает вместе с `ym:ad:` и `ym:ev:`.** Метрика отвечает на такую пару 400,
поэтому сервер фильтр не ставит и пишет об этом в `_meta.notes`. В таком отчёте роботы есть.

**Сравнение периодов без дат сравнивает период сам с собой.** У `metrika_stat_comparison` даты
необязательны: не задали — Метрика подставит своё окно в оба набора, и ответ будет выглядеть
полностью валидным при одинаковых числах слева и справа. Сервер это замечает и пишет в
`_meta.notes`; всегда задавайте `date1_a`/`date2_a`/`date1_b`/`date2_b` явно.

**`total_rows` больше числа строк — данных не всё.** У Метрики есть свой предел выдачи, и
отсутствие `limit` в запросе не означает, что пришло всё. Сервер кладёт в `_meta` поля
`rows_returned`, `rows_total` и `truncated` — сверяйтесь с ними, а не с длиной `data`.

**Сэмплирование включается само.** `accuracy` по умолчанию `medium`. Признак — поля `sampled`
и `sample_share` в ответе; сами числа никак не помечены. Полная выборка — `--accuracy full`,
и это не требует Метрики Про. Сильнее всего страдает хвост: редкие URL и фразы не попадают
в отчёт не нулями, а отсутствующими строками.

**Модель атрибуции меняет картину источников, а документация про неё врёт.** Доля каналов
при разных значениях `attribution` отличается в разы — данные те же, «источник» назначается
по-разному. Документация обещает, что по умолчанию `last`; в эхо-запросе приходит
`CROSS_DEVICE_LAST_SIGNIFICANT`. Модель, по которой посчитан отчёт, всегда написана в
`data.query.attribution` — её и надо называть рядом с числом. Устаревшие значения
(`first`, `lastsign`) не отвергаются, а молча подменяются другими.

**Фильтр по русскому названию возвращает ноль.** `lang` по умолчанию `en`, поэтому
`ym:s:trafficSourceName=='Переходы из поисковых систем'` даёт 200 и пустой результат —
неотличимо от «такого сегмента нет». Фильтруйте по идентификаторам: `ym:s:trafficSource=='organic'`.

**Фильтр по метрике не меняет `totals`.** Он применяется к уже сгруппированным строкам, а не
к исходным данным. Строки в ответе не сложатся в итог, и это не ошибка счёта.

**Часовой пояс — счётчика, а не ваш.** Сутки в отчёте начинаются по таймзоне счётчика.
Сравнивая с другим источником данных, сперва убедитесь, что границы суток совпадают.

## Изменение данных выключено

Методы, помеченные в справочнике «меняет данные», без `METRIKA_ALLOW_WRITES=1` отказывают,
не обращаясь к API. Это не придирка: удалённую цель или счётчик восстановить нечем, а история
достижений цели не восстанавливается вообще.

Прежде чем включать — спросите человека прямым вопросом, назвав, что именно будет изменено.

## Если работаете с Метрикой постоянно

Тот же сервер есть как MCP: инструменты появляются в клиенте, и команду набирать не нужно.
Установка и подробности — [github.com/artgas1/yandex-metrika-mcp](https://github.com/artgas1/yandex-metrika-mcp).

Скилл и MCP — один и тот же код, поэтому и гарантии одинаковые. Разница в цене: MCP держит
описания инструментов в контексте постоянно, скилл читается только когда речь зашла о Метрике.
