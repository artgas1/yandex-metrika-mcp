# Безопасность

## Чем этот сервер НЕ является

Не граница безопасности. Сервер выполняет запросы к API Яндекс Метрики от имени
OAuth-токена, который вы ему выдали, и не сужает права этого токена. Всё, что
может токен, может и любой, кто управляет вызовами инструментов. Ограничение
прав — на стороне Метрики (выдайте токен с нужным доступом), а не здесь.

Не фильтр содержимого. Значения в отчётах — поисковые фразы, URL, заголовки
страниц, названия целей — пишут посетители вашего сайта и редакторы счётчика.
Это данные, а не инструкции; сервер отдаёт их как есть и говорит об этом
в `instructions`.

## Что сервер делает для защиты

- **Запись выключена по умолчанию.** Инструменты `PUT`/`DELETE` и удаляющие
  `POST` не объявляются вовсе, пока не задан `METRIKA_ALLOW_WRITES=1`.
  Отсутствие в `tools/list` надёжнее отказа на вызове: модель не может позвать
  то, чего не видит.
- **Узкая поверхность по умолчанию.** Профиль `core` — десять инструментов.
  Полный каталог включается явно (`METRIKA_PROFILE=all`).
- **Аннотации на всех инструментах.** `readOnlyHint` / `destructiveHint` /
  `idempotentHint` / `openWorldHint` проставлены по HTTP-глаголу и проверяются
  тестом; клиент может на них опираться при авто-подтверждении.
- **Схемы закрыты.** У каждого инструмента `additionalProperties: false`.
- **Секреты не возвращаются.** Значения параметров `token`, `oauth_token`,
  `access_token`, `password`, `secret` вырезаются из адреса запроса в любом
  ответе и в тексте ошибки.
- **Подмена адреса API объявляется.** Если задан `METRIKA_API_BASE`, сервер
  пишет в stderr, что токен уходит не на `api-metrika.yandex.net`.
- **Ответы ограничены по размеру** с явной отметкой об урезании.

## Куда уходит трафик

Только на `https://api-metrika.yandex.net` — если не переопределено переменной
`METRIKA_API_BASE`. Других сетевых адресатов у сервера нет: телеметрии,
аналитики и обращений к сторонним сервисам он не делает.

## Токен

`YANDEX_API_KEY` читается из окружения процесса и никуда не пишется: ни в файл,
ни в stdout, ни в тело ответа. Держите его в `env`-секции записи сервера в
конфигурации клиента, а не в аргументах командной строки — аргументы видны в
`ps` любому процессу на машине.

## Как сообщить об уязвимости

Приватно, через [GitHub Security Advisories](https://github.com/artgas1/yandex-metrika-mcp/security/advisories/new).
Не открывайте публичный issue.

Ответ — в течение 7 дней. Если уязвимость подтверждается, исправление выходит
отдельной версией, а затронутые версии помечаются через GitHub Advisory,
чтобы `npm audit` увидел их у тех, кто уже установил пакет.

Удаление пакета из npm аварийным люком не является: уже установленные копии оно
не убирает. Поэтому канал отзыва — версия плюс advisory, а не unpublish.
